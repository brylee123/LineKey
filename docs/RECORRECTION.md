# Revisiting committed words (0.7.5)

Tap within an earlier word or select that entire word to show spelling alternatives in the suggestion bar. For words committed by LineKey in the current editor session, the bar restores the original literal input and up to 32 original suggestions. Thus choosing `eaten` from an ambiguous `sztech` input does not discard `watch` if it was originally offered. The saved list retains its original order and casing; later typing or a keyboard mode change does not recompute it from the chosen spelling. Both Mini and expanded modes use the same behavior.

Choosing an alternative replaces only that word's validated UTF-16 range. Existing spaces, adjacent sentence punctuation, and later text stay in place. There is no automatic trailing space during recorrection. Immediate Delete restores the previously committed spelling, and the original alternatives remain available for another choice. Replacements of different lengths shift later recorded ranges. Exact whole-word selections in either direction are supported; partial or multiple-word selections are left to ordinary editor behavior.

RecorrectionHistory is a pure Java, bounded session cache: at most 64 committed words, at most 32 saved alternatives each, and an editor snapshot capped at 65,536 UTF-16 code units. It stores the original literal input and candidate strings, not a new permanent touch log. Local dictionary learning remains a separate opt-in feature. The cache is never written to preferences/files, backed up, or sent over the network. It is cleared when input finishes/restarts or another field starts; private, password, email/URL, numeric/phone and other literal/raw editors do not supply snapshots or show recorrection choices.

Selection callbacks and public extracted-text monitor notifications (including text edits without cursor movement) refresh the current word. Each editor update rebases unaffected ranges using the common unchanged prefix/suffix. Overlapping external edits discard the old evidence. If identical repeated text makes the edited position ambiguous, evidence in the ambiguous band is discarded rather than assigned to a potentially different occurrence. Identical words at different positions have separate records. Before replacement, a fresh editor snapshot must identify the same word, range and evidence; stale suggestions cannot replace an unrelated range. Moving or oversized extraction windows discard uncertain history. The session snapshot and original strings are retained only in memory within these bounds.

For text without saved evidence (including words from an earlier session), the keyboard offers ordinary spelling matches for the visible word. It cannot reconstruct past approximate taps that were never saved. This is spelling correction, not semantic synonym lookup. Editors must support public InputConnection text extraction and selection/replacement operations; unsupported editors simply retain their normal input behavior. The base vocabulary and language model are unchanged.

Native regression uses a fixed trace whose nearest-letter transcription is `sztech` and whose initial shortlist includes both `eaten` and `watch`. It selects `eaten`, types a later word, taps the earlier editor text, and selects `watch`; it also covers whole-word selection, both keyboard modes, repeated choices, length changes, undo, prefix edits, duplicate word positions, overlapping edits, a password field, untracked spelling correction, and alternatives saved by automatic Space correction. Pure Java checks cover cache limits and range rebasing. Build/emulator results are recorded in VERIFICATION.md after execution.
